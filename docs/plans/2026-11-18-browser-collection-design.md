# 商家后台Agent自动采集方案

状态：用户已确认。本文件按最后澄清重写：仅为定时任务，与消息机器人无关。

沿用现有FastAPI、APScheduler、SQLAlchemy数据库、NormalizedOrder与套餐拆分服务，不另建调度框架或订单库。原官方API连接器保留并标记“暂不可用”，worker不再执行API轮询。

流程：定时到点或网页手动排队 → 启动指定本地agy/dsh → 传入任务提示词及实际数据库连接 → Agent通过Chrome DevTools MCP连接CDP → 自行采集美团/饿了么/京东商家后台 → 调用本地数据库技能写入 → 重新查询与后台核对 → 中文报告进入进程日志。

启动器只负责启动、传参和进程生命周期，不实施固定采集协议，不要求返回JSON再由代码导入，不设置Agent沙箱、工具/网址白名单、SQL只读或任务运行时限。选择的CLI不可用时明确失败，不改用其他执行器。网页登录权限与CSRF照常保留。

AgentTask保存命令、参数、提示词、变量与间隔；AgentRun保存每次命令/提示词快照、队列/运行状态、PID、退出码、日志路径和时间。条件更新认领运行记录，避免同一运行被重复启动。模板错误记单任务失败，其他队列继续运行。订单继续按门店+订单号更新，套餐组件追溯原订单原商品。

网页提供任务管理、手动执行和日志查看。三平台参与统一订单、销量和MCP筛选。数据库技能支持查表、任意SQL读写、调用现有服务入库和独立核对。默认提示词及技能随wheel分发。

验证范围：自动调度、本地进程、数据库技能插入套餐订单和独立核对已用临时数据库测试；浏览器页面另行验证。实际模型授权和三个商家后台未联调，不能宣称已拿到生产订单。Docker镜像目前不包含agy/dsh/Node，Agent worker推荐原生部署并使用已配置模型与CDP的服务用户。
